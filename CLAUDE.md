# Knotty

- The interface and every text for the person are in Mexican Spanish; the code (names, files, logic and comments), the saved data, the prompts and the documentation are in English. The prompts ask the expert to write everything the person reads in Spanish (D33 in `docs/PROPUESTA.md`). `docs/PROPUESTA.md` and `docs/carpinteria/` are still in Spanish.
- Measures in millimetres. Hexagonal architecture: `src/architecture.test.ts` checks the boundaries between layers and between the groups of `src/domain/` (`materials`, `design`, `estimate`, `checks`, `editing`, `furniture`, `session`; no cycles).
- `docs/PROPUESTA.md` is the living document: decisions, invariants and open questions (the diary of each delivery goes in its PR). `CONTRIBUTING.md` says how to verify a change by what it touches (levels and table). `docs/workflows.md` says what to do and where each thing goes by what one wants to achieve (a request the chat understands alone, a new option or piece of furniture, a ficha with the expert).
- `docs/carpinteria/` is the domain reference (plywood, joints, finishes, measures, structure, glossary); if two documents disagree, `valores-de-referencia.md` wins. If asked «contesta como <experto>» or for a «mesa redonda», read `docs/carpinteria/expertos.md` and answer with that judgment and that voice.
- Before a PR: `npm run lint`, `npm run typecheck` and `npm test`. `npm run compare` and `npm run autonomy -- --ask` call real providers and cost tokens: by hand only.
- Spotlight (`Ctrl+K` or `⌘K`, and the magnifier in the Studio's header; for everyone): it searches the furniture by name, room, style or model (its code) and what is chosen takes the Studio. It swaps at once when the open design is a ficha as it was opened, and asks first when something of the person's would be lost (`swapLoss` in `src/ui/spotlight/swap.ts`). The link button beside it copies an address that opens that ficha under the same rule, with the options of the whole piece when they are not the ficha's own (`?ficha=KC-MES-03&acabado=paint&armado=bolts`); a new option is a line in `LINK_OPTIONS` (`src/ui/spotlight/link.ts`). The home keeps its filter in the address (`?q=mesa&cuarto=comedor`).
- Design files (D75): «Descargar mi diseño» in the Studio hands the whole session as a `.knotty` file (gzip over a versioned JSON envelope, `src/domain/session/file.ts`), and «Abrir un archivo» on the home opens one under the same `swapLoss` rule. Every loss notice offers «Descargar y …» first (`src/ui/files/DownloadFirst.tsx`). Anything that replaces the open design goes through `opened()` in `src/ui/store/session.ts`; a design that is already whole enters with `openDesign(state)`.
- «Mis muebles» (D76, UI-87): a sheet over any screen (`src/ui/library/`, opened from the home and the Studio) with five places where the person saves the open design under a name. The open design still saves itself; a place changes only when the person says so. Storage is IndexedDB (`src/adapters/persistence/indexedDb.ts` for the open design, `library.ts` for the places, port `src/ports/DesignLibrary.ts`), with localStorage as the fallback and then no places. A path that puts another design in the Studio calls `library.detach()`, or «Guardar los cambios» would write it over the place of the previous one.
- «Ver en tu espacio» (`src/ui/room/`, D74): from a ficha's adjustment screen or the Studio, the piece opens placed in an example room to combine it with other fichas. The room lives in memory only (`#space` carries no data) and its furniture are previews: one piece at a time goes to the Studio, which still owns construction, history, materials and PDFs. `layout.ts` holds the spatial checks and says what is not checked.
- Debug access: the Konami code (↑↑↓↓←→←→BA), `Ctrl+Shift+D` or the switch in settings. With it the Studio adds the «Hallazgos» tab (what Knotty computes of the design, with the pieces by name and «Ver en el 3D»), the provider and model switch, and «Exportar ficha» (the candidate file for `probe`, only if the design is still its plan); the spotlight adds each ficha's version and findings (the same ones `probe` keeps). There is no bench or log in the app: `npm run compare` runs the fixed cases of `src/application/bench/cases.ts`, and `npm test` checks every variant of each module (one with findings is a Knotty bug).
